# BETA Client

본 저장소는 [BETA-BasEball-Together-Always/BETA-Client](https://github.com/BETA-BasEball-Together-Always/BETA-Client)를 포크하여 작업한 **BETA Client 개인 레포지토리**입니다. 아래는 **본인(Khaneul1)이 프로젝트에 기여한 커밋 히스토리**와 **담당·구현 범위**를 바탕으로 정리한 문서입니다.

## 1. 프로젝트 개요

| 항목 | 내용 |
|------|------|

## 2. 신규 구현 및 전담 기능

아래는 **처음부터 설계·구현에 참여했거나 화면·도메인을 주도한 영역**입니다.

### 2.1 애플 로그인

- **내용**: `expo-apple-authentication` 기반 iOS 애플 로그인 플로우를 앱 인증 스택에 통합.
- **포인트**: 네이티브 모듈이 포함된 dev-client 빌드와의 호환, 토큰·세션 처리 시 기존 이메일/소셜 계정과의 정합성.

### 2.2 홈 화면 및 전체/팀 게시판

- **내용**: 메인 탭의 홈·팀별 피드 진입, 리스트·썸네일·팀 라벨 표시.
- **후속 QA**: 팀 라벨 `lineHeight`·색상 조정, 상단 바·헤더 간격, 인기 피드 썸네일에 **등록 이미지 개수 배지** 배치, 예외 처리·로딩 동작 정리.

### 2.3 게시글 상세 · 감정 표현 토글 · 리액션 바

- **내용**: 상세 화면에서 감정(리액션) 토글, 하단/고정 영역의 인터랙션 UI.
- **후속 QA**: 좋아요/감정 취소 시 **느리게 반영되던 UI** 개선, 실시간 동기화 이슈(아래 3.2 참고).

### 2.4 댓글 등록·수정·삭제 및 좋아요 토글

- **내용**: 댓글·답글 CRUD, 좋아요 토글, 리스트와 입력창 연동.
- **후속 QA**: 댓글 `lineHeight`, 입력창 포커스 시 **과도한 자동 스크롤** 완화, 키보드·인풋 높이에 맞춘 **하단 스크롤**, 등록 버튼이 키보드 포커스 시 사라지지 않도록 처리.

### 2.5 게시글 작성 페이지

- **내용**: 본문·이미지·팀 라벨 등 작성 플로우.
- **후속 QA**: 작성 화면에서 **팀 라벨 색상 미적용** 수정, 해시태그·본문 중간 삽입·수정 시 **태그 누락/중복 등록** 문제 해결.

### 2.6 마이페이지 · 프로필 설정 · 타 유저 프로필

- **내용**: 내 정보·설정, 타인 프로필 조회 등 프로필 도메인 화면.

### 2.7 회원가입 완료 페이지

- **내용**: 가입 플로우 마지막 단계의 완료 UI 및 상태 처리.

## 3. 기존 코드 수정·최적화 및 QA 대응

upstream에 이미 존재하던 모듈을 **기능 보강·버그 수정·UX 통일**한 범위입니다.  
(일부는 커밋 메시지에 `QA Section`, `feat`, `chore` 등으로 구분되어 있습니다.)

### 3.1 야구네컷(프레임 선택·편집·공유)

- **아키텍처 변경(본인 주도)**: 기존에는 **프레임 슬롯(캔버스 위 사진 영역)**과 **하단 이미지 슬롯 리스트**가 한 덩어리로 묶여 있어, 한쪽을 바꾸면 다른 쪽이 의도치 않게 같이 움직이거나 URI가 덮어씌워지는 문제가 있었습니다. 이를 **이미지 슬롯 리스트 상태와 프레임 내부 슬롯에 그려지는 이미지 상태를 분리**하여, 리스트 조작과 프레임 미리보기가 **서로 독립적으로** 동작하도록 **데이터 흐름·스토어/로컬 상태 설계를 전면 수정**했습니다.
- **컴포넌트화·관심사 분리(본인 주도)**: 당시 코드베이스에서는 편집·미리보기·툴 패널·오버레이 등이 **분리되지 않은 채 한 흐름에 뭉쳐 있던 부분**이 많았습니다. 이를 **화면·도메인 단위로 컴포넌트를 나누고**, 재사용 가능한 단위(툴바, 사진/프레임 도구 패널, 오버레이 등)로 **책임을 쪼개어** 상태 변경이 한곳에만 몰리지 않도록 정리했습니다. 그 결과 슬롯 리스트·프레임 캔버스 로직을 손볼 때 **범위를 예측하기 쉬운 구조**로 맞출 수 있었습니다.
- **이미지 슬롯 리스트 기능(본인 추가)**:
  - 리스트에 **사진 추가**, **썸네일 탭으로 특정 슬롯과 매핑·교체**, **순서 변경**(드래그 또는 갤러리/촬영으로 슬롯에 넣는 방식 등 화면 설계에 맞는 입력 경로)까지 **한 흐름으로 제어**할 수 있게 구현했습니다.
- **버그·QA 대응**: `develop` 기준으로는 **데이터 구조 변경**, **덮어쓰기·이전 이미지 잔존** 해결, **SelectScreen** 포커스 시 **구단·프레임 선택 초기화** 등이 이어졌고, feature 브랜치 작업에서는 예컨대 `feat: 인증 흐름 개선 및 PhotoBooth/UI 전반 리팩토링`, `야구네컷 uri 덮어씀 문제 해결`, `이미지 생성 및 uri 저장 로직 수정` 등의 커밋으로 같은 도메인을 안정화했습니다.
- **ShareScreen 등**: 닫기 아이콘 배치 등 UI 조정, **1차 스플래시 제거** 등 공유·진입 흐름 정리.

### 3.2 피드·게시글 실시간 반영

- 게시글 **수정/삭제**, 댓글·감정 **등록 후 목록·상세에 바로 반영**되도록 캐시/쿼리 무효화·낙관적 업데이트 등 정리.
- **피드 동기화**, 소셜 로그인 **세션 충돌** 완화, **네트워크 오류 시 메시지·UX** 개선.

### 3.3 네이버 / 카카오 로그인

- 네이버 로그인 로직 수정, 소셜 로그인 **이메일 중복 시 모달** 동작 정리.
- `.env` 도입 및 설정과의 연동(민감 정보는 저장소에 포함하지 않음).

### 3.4 약관 동의 · 회원가입 단계(이메일, 닉네임, 구단, 성별/나이)

- 단계별 **프로그레스 헤더** UI 통일·컴포넌트 분리.
- 인디케이터·서브 텍스트 색상, **“사용 가능한 닉네임”** 문구 등 디테일.
- 이탈 후 재진입 시 **이전 단계 데이터 유지** 등 플로우 안정화.

### 3.5 스플래시 스크린

- 노출·전환 타이밍 및 UI/UX 조정(불필요한 1차 스플래시 제거 등).

### 3.6 계정 탈퇴

- **30일 유예**, 재로그인 시 **철회(취소)** 가능한 정책 반영 및 UI/로직 정리.

### 3.7 알림 설정(추가 기여)

- **개별 알림 토글** 활성화 시 발생하던 **에러** 수정.
- **전체 알림 토글**을 켤 때 **개별 알림 토글도 함께 켜지는** UX를 의도에 맞게 정리(원래 다른 분 작업 영역이었으나 본인이 수정).

## 5. 문제점과 해결 과정에서 배운 점

### 5.1 React Native·Expo에서의 상태와 UI

- **문제**: 목록·상세·댓글이 **동시에 열려 있을 때** 한쪽에서의 액션이 다른 쪽에 늦게 반영되거나, 키보드·스크롤이 겹치며 UX가 깨짐. 게시글 상세에서는 **댓글 입력 포커스·키보드 높이·리스트 최하단 스크롤**이 한꺼번에 얽히기 쉬움.
- **접근**: TanStack Query의 **무효화 범위**, 화면별 `refetch` 타이밍, `Keyboard`·`FlatList` 조합을 화면별로 나누어 조정. 좋아요·감정처럼 **즉시 반응이 기대되는 액션**은 터치 후 UI가 끊기지 않도록 **낙관적 업데이트·쿼리 무효화 순서**를 맞춤.
- **배운 점**: “한 화면만 맞추기”가 아니라 **네비게이션 스택·탭 간 데이터 일관성**을 설계 단계에서 고려해야 함. 모바일은 **레이아웃·키보드·스크롤이 한 화면의 상태**라서, 영역만 나누는 식의 사고로는 부족할 때가 많음.

### 5.2 소셜 로그인·세션

- **문제**: 이메일 중복, 로그아웃 충돌, provider별 토큰 처리 차이. 시뮬레이터와 달리 **실기기·스토어 빌드**에서만 드러나는 설정 이슈와 구분해야 할 때도 있음.
- **접근**: 모달 분기·에러 메시지 명확화, 세션 스토어와 API 응답 코드 매핑 정리. iOS **URL 스킴·대소문자**, `app.config` 플러그인·의존성 버전이 로그인 성패에 직결되는 경우가 많아 **클라이언트 로직과 네이티브 설정을 같이** 추적함.
- **배운 점**: OAuth는 **해피 패스**만 구현하면 안 되고, **엣지 케이스·중복 계정**을 제품 요구사항과 함께 정의해야 함. “실패” 한 줄이 아니라 **다음 행동(다른 로그인 시도·고객센터 등)**까지 연결되는 문구·모달이 안전함.

### 5.3 이미지·슬롯·네이티브에 가까운 UX(야구네컷)

- **문제**: 프레임 안 슬롯과 하단 **이미지 슬롯 리스트**가 결합되어 **덮어쓰기·잔상**, 리스트 조작 시 프레임과 **엇박자**가 나는 등 **상태 머신**이 복잡해졌습니다.
- **접근**: **리스트용 순서·URI 배열**과 **프레임에 그릴 슬롯 매핑**을 분리하고, SelectScreen 등에서는 포커스·재진입 시 **초기화 조건**을 명시했습니다. 편집 화면은 **컴포넌트 단위로 책임을 나눈 뒤**에야 위 분리가 유지됨.
- **배운 점**: 미디어 편집류는 **“사용자가 보는 리스트”와 “캔버스에 그려지는 결과”**를 같은 소스에 억지로 묶으면 버그가 반복되므로, **경계를 나누는 설계**가 우선입니다. 촬영·갤러리·캡처·공유까지 이어지는 **파일 URI 수명**도 플랫폼별로 점검할 필요가 있음.

### 5.4 푸시·알림 토글

- **문제**: 개별 토글 시 에러, 전체/개별 연동 UX 불일치.
- **접근**: 토글 간 의존 관계(전체 ON → 개별 동기화 등)를 **사용자 기대**에 맞게 정리하고 API/로컬 상태를 맞춤. FCM 토큰 등록·갱신과 **설정 화면 스위치 상태**가 어긋나지 않게 동기화.
- **배운 점**: 알림·권한은 **UI 스위치 한 개가 백엔드·푸시·OS 설정**과 연결되므로 화면만 고친다로 끝나지 않는 경우가 많음. 기존 플로우를 이어받을 때도 **시나리오 기준 검증**이 중요함.

### 5.5 게시글·해시태그·리치 텍스트

- **문제**: 작성·수정 시 **본문 중간 해시태그 삽입**, 수정 시 **태그 누락·순서 역전**, 화면에 보이는 문자열과 서버 페이로드가 어긋날 여지.
- **접근**: 파싱·직렬화 규칙을 한 흐름으로 정리하고, 수정 플로우는 작성 플로우와 **필드 단위로 대조**해 누락을 막음.
- **배운 점**: 입력 영역이 길어질수록 **표시용 문자열**과 **전송용 모델**을 분리해 두지 않으면 QA에서 같은 유형의 버그가 반복됨.

### 5.6 피드·인기글·목록 UX

- **문제**: 인기 피드 정책(노출·정렬)·썸네일 배지·팀 라벨·빈 상태 등 **정책과 UI가 동시에 움직이는 영역**에서 예외가 많음.
- **접근**: 카드·리스트에서 **이미지 개수·팀 라벨** 등 메타 정보를 공통 규칙으로 표시하고, 정책이 바뀌어도 **한 컴포넌트 계약(props, 스키마)** 안에서 깨지지 않게 맞춤.
- **배운 점**: “피드 화면 하나”도 탭·정책·디자인 QA가 겹치면 **작은 스타일 하나가 전체 일관성**을 흔들 수 있음.

### 5.7 네트워크·에러 UX·온보딩

- **문제**: 토스트 한 줄만으로는 **재시도·원인(타임아웃 vs 권한 vs 서버)** 구분이 어렵고, 회원가입 단계가 길수록 **이탈·재진입 시 상태 복원** 이슈가 생김.
- **접근**: 연결 상태(NetInfo 등)와 맞물려 **오프라인·복구** 메시지를 정리하고, 단계별 가입은 **완료한 스텝·임시 저장**을 코드에서 추적 가능하게 둠.
- **배운 점**: 에러 처리는 **개발자용 로그와 사용자 메시지**를 분리하고, 온보딩은 **“어디까지 왔는지”가 상태로 남아야** 유지보수가 쉬움.

### 5.8 계정·정책 반영(탈퇴 유예 등)

- **문제**: 탈퇴 **유예 기간**, 재로그인 시 **철회** 같은 규칙은 문구뿐 아니라 **라우팅·세션·API 응답**과 일치해야 함.
- **접근**: “탈퇴 진행 중 / 일반” 등 상태를 나누고, 설정·모달·로그인 진입에서 **같은 조건을 참조**하도록 정리.
- **배운 점**: 정책 변경 시 **프론트 가드 조건**이 가장 먼저 흔들리기 쉬우므로, 조건식을 화면마다 복붙하기보다 **한 레이어에서 해석**하는 편이 안전함.
